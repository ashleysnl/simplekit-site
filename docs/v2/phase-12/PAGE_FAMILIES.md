# Page-family specifications and reference review

The saved [approved mobile reference](../../design-reference/simplekit-v2-target.png) governs navy/blue/teal atmosphere, display/sans hierarchy, light surfaces, restrained elevation and clear next steps. It is a homepage composition, not a calculator information architecture. These responsive reference pages are derived proposals for later migrations; they do not rewrite existing financial advice or mark routes redesigned.

| Family | Layout and required semantics | Responsive reference |
| --- | --- | --- |
| Homepage | Retain existing compact hero/coastal composition, search/suggested questions, qualified trust, goals/Featured and optional onboarding. Preserve all 22 destinations, 44px controls, no-JS discovery and ephemeral answers. Adopt a shared shell only after comparing existing screenshots and validating interactions. | [Verified Phase 11 interim views](../phase-11/INTERIM_PREVIEW_REVIEW.md). |
| Directory | Shared shell, clear page heading, search/goal anchor navigation, all seven category groups and exactly one primary listing per calculator. Preserve current filtering, ordinary links and keyboard/focus feedback; no competing route list. | Existing [directory baselines](../phase-11/GALLERY.md); Phase 13 applies the shared shell and interior spec. |
| Editorial/hub/support | Compact shared header, wrapped breadcrumb, concise intro, 44rem reading width, section navigation before content on phones / beside content on desktop. Open text rhythm instead of nested decorative cards; restrained callouts, sources, native disclosures, local-scrolling tables and related canonical tools. Hub/short-guide grids use the same type/surfaces; legal/support pages preserve all original copy. Never invent authors/dates. | [Editorial review HTML](references/editorial.html); mobile/tablet/desktop captures linked from the verification report. |
| Interactive calculators | Same shell/heading and an explicit inputs → results flow. One mobile column; desktop balanced form/results columns. Units/help/errors remain visible, KPIs stay readable, chart has data/text alternative, tables retain columns via local scrolling, exports/assumptions/related content remain close. Stateful wizard/dashboard tools adapt these primitives to their existing workflows; no generic form replaces Retirement scenarios or Budget rows. | [Calculator review HTML](references/calculator.html); fixed illustrative data, not a financial calculator. |
| Component/state reference | Native labelled scalar fields/selects/radios/checkbox/switch/slider, visible focus/error/disabled states, notes/disclosure, empty/loading examples, chart/table/export and shell navigation. | [State workbench HTML](references/components.html). |

HTML references use root-relative assets and the review-only controller. Render through `tests/v2-system-browser.cjs` against the local generated preview; the test intercepts only reference URLs. They are excluded from `dist/`, sitemap and public routes. Screenshot galleries are portable review artifacts.

Functional deviations from the raster are deliberate: readable text/44px touch areas, preserved citations/disclosures/data, local table scrolling, keyboard-visible focus and purpose-specific calculator flow. “Suggested/Featured” avoids unsupported popularity claims; privacy copy qualifies existing analytics. Owner design acceptance belongs to Phase 17 after the full site is implemented, not this reference exercise.
